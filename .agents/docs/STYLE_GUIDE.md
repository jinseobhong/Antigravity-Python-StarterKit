## 📌 1. 목적 및 기본 철학 (Purpose & Philosophy)

본 스타일 가이드는 Antigravity 기반 프로젝트에서 작성되는 모든 엔지니어링 문서의 **가벼운 구어체 및 캐주얼한 표현을 원천 배제**하고, 국제 소프트웨어 표준(RFC / ISO / IEEE)에 부합하는 **엄밀성, 객관성, 추적 가능성, 고신뢰도 기술 문체**를 확립함을 목적으로 한다.

## 🏛️ 2. 핵심 5대 작성 원칙 (5 Core Principles)

### 2.1 절제된 기술 공학 문체 (Dignified Technical Tone)
1. **구어체 및 감정적 수식어 전면 배제**: *"매우 훌륭한"*, *"완벽한"*, *"엄청난"* 등의 주관적 수식어를 금지하고, 객관적 인과관계와 사실만을 기술한다.
2. **명사형 종결 및 정중한 기술체 준수**: 문장은 명사형 종결(~함, ~을 수행함, ~로 정의됨) 또는 절제된 기술 공학 문체로 종결한다.
3. **이모지(Emoji) 절제**: 문서 본문 내 불필요한 장식용 이모지 남발을 금하며, 상태 닻(Status Marker: `[x]`, `[>]`, `[⏸️]`)이나 핵심 경고 블록에만 제한적으로 사용한다.

### 2.2 표준 메타데이터 헤더 의무화 (Metadata Header Mandate)
모든 정식 사양서, 계획서, 설계도, 보고서는 최상단에 다음 **표준 메타데이터 테이블**을 필수로 포함하여야 한다:

```markdown
| 항목 | 내용 |
| :--- | :--- |
| **문서 ID** | `[DOC-TYPE-NUM: 예 - SPEC-ARCH-001]` |
| **문서 버전** | `[vX.Y.Z: 예 - v1.0.0]` |
| **작성 일자** | `[YYYY-MM-DD]` |
| **상태** | `[DRAFT | REVIEW_REQUIRED | APPROVED | DEPRECATED]` |
| **작성자 / 승인자** | `[AI Architect / Human Lead]` |
```

### 2.3 RFC 2119 표준 요구사항 키워드 준수
요구사항 및 가드레일 정의 시 모호한 표현을 금지하며, 다음 대문자 표준 키워드를 사용한다:
- **`MUST` / `SHALL` / `REQUIRED` (필수)**: 절대적으로 지켜야 하는 필수 항목.
- **`MUST NOT` / `SHALL NOT` (절대 금지)**: 원천적으로 금지되는 항목.
- **`SHOULD` / `RECOMMENDED` (권장)**: 합당한 사유가 없는 한 따라야 하는 권장 항목.
- **`MAY` / `OPTIONAL` (선택)**: 상황에 따라 선택 가능한 재량 항목.

### 2.4 객관적 사실 및 정량적 기술 (Objective & Quantifiable)
- **금지**: *"테스트를 빠르게 돌려 문제가 없음을 확인했습니다."*
- **의무**: *"pytest 단위 테스트 5종 실행 결과: 0.42s 소요, 100% Pass (0 failed, 0 errors) 확인 (`PROVEN`)."*

### 2.5 시각적 구조화 및 다이어그램 우선 (Visual Topology)
- 단순 줄글 나열을 지양하고, 시스템 구조와 데이터 흐름은 **Mermaid 다이어그램(Class/ERD/Flowchart)**, **비교 매트릭스 표(Table)**, **Fenced 코드 블록**으로 구조화하여 표현한다.
