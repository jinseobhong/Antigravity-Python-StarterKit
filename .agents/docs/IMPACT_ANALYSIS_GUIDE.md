## 📌 1. 목적 및 철학 (Purpose & Philosophy)

본 규격서는 Antigravity 생태계 내 모든 작업 완료 보고 및 기술 자문 시, 단순한 파일 목록 나열이나 판에 박힌 기계적 요약을 원천 배제하고, **1인 개발자가 시스템에 일어난 변화와 비즈니스적 가치를 직관적이고 생생하게 이해할 수 있도록 심층 영향도를 분해하는 3계층 프레임워크(3-Tier Deep-Dive Framework)**를 확립한다.

---

## 🏛️ 2. 시스템 영향도 3계층 심층 분석 프레임워크 (3-Tier Framework)

모든 작업 완료 보고 시 에이전트는 다음 3대 계층을 입체적으로 분해하여 기술해야 한다:

### 2.1 제1계층: 💾 실제 데이터 흐름 추적 (Data Flow Pipeline Trace)
- **정의**: 변경 전후의 데이터가 메모리(RAM)와 디스크(Disk), 혹은 상하위 모듈 사이에서 실제로 어떻게 이동하고 변환되는지 추적한다.
- **표현 방식**: Mermaid 시퀀스/플로우 다이어그램 또는 단계별 넘버링 파이프라인.
- **핵심 질문**: *내가 어떤 액션을 취했을 때, 내부에서 데이터가 어떤 순서로 처리되고 어디에 안전하게 도달하는가?*

---

### 2.2 제2계층: 🛡️ 방어된 구체적 결함 시나리오 (Prevented Failure Scenarios)
- **정의**: '만약 본 구현이 없었거나 잘못 설계되었다면 발생했을 실제 끔찍한 버그나 엣지 케이스'를 구체적 실패 시나리오로 제시하고, 본 구현이 이를 어떻게 방어하는지 설명한다.
- **핵심 질문**: *이 코드가 없었으면 어떤 사고가 터졌을 것이며, 어떻게 100% 방어되었는가?*
- **다루는 영역**: 데이터 깨짐, 비정상 종료 시 롤백, 동시성 락, 1:N 관계 불일치, 타입 오류, 메모리 오염 등.

---

### 2.3 제3계층: 🧑‍💻 1인 개발자 체감 변화 및 차기 코드 예시 (DX & Next-Step Code)
- **정의**: 추상적인 원론을 배제하고, **'내일 사용자가 작성할 다음 단계 코드가 얼마나 단순하고 직관적으로 바뀌는가'**를 3~5줄 내외의 구체적인 실행 코드 스니펫으로 증명한다.
- **핵심 질문**: *이 작업 덕분에 내일 내 코드가 얼마나 편해지고 뇌 용량을 아낄 수 있는가?*
- **다루는 영역**: 저수준 처리의 캡슐화, 단일 진실(SSOT) 접근성, 간결한 유스케이스 호출 예시.
