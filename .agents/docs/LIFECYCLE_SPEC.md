# 2-Phase Development Lifecycle & 4-Track Agile Router Specification

본 문서는 Antigravity 환경에서 인간과 AI가 페어 프로그래밍을 수행할 때, **모든 사용자 입력을 실시간 4대 트랙으로 동적 분류(Classification)하고 최적의 경로로 유연하게 처리하는 애자일 라우팅 및 2-Phase 라이프사이클 공식 명세서**입니다.

---

## 🎯 1. 4대 입력 분류 및 동적 트랙 라우팅 (4-Track Intent Matrix)

```text
┌─────────────────────────────────────────────────────────────────────────────────┐
│ 📥 사용자 입력 인입 (User Prompt Arrival)                                       │
└──────────────────────────────────────┬──────────────────────────────────────────┘
                                       ▼
                  【마스터 인텐트 분류기 (Intent Classifier)】
                                       │
 ┌─────────────────┬───────────────────┼────────────────────┬────────────────────┐
 │                 │                   │                    │                    │
 ▼                 ▼                   ▼                    ▼                    ▼
[⚡ Track 1]      [🔬 Track 2]        [🏛️ Track 3]         [💬 Track 4]         [⏸️ Interrupt]
패스트 트랙       스파이크 탐색       표준 아키텍처        일반 대화/무관 질의   작업 끼어들기
(오타/단순수정)   (실험/프로토타입)   (신규기능/구조변경)  (지식/잡담/설명)     (기존작업 일시정지)
```

| 트랙 | 대상 및 시나리오 | 프로세스 및 통제 강도 | 승인 및 문서화 |
| :--- | :--- | :--- | :--- |
| **⚡ Track 1 (Quick)** | 오타, 1~2줄 경미한 패치, 주석/서식 정렬 | 계획서/모달 생략, 즉시 수정 | Diff 보고 & `CURRENT_STATE` 1줄 정리 |
| **🔬 Track 2 (Spike)** | 기술 조사, 라이브러리 검증, 프로토타입 | `scratch/`에서 자유 실험 (비파괴) | 결과 요약 보고 후 도입 여부 결정 |
| **🏛️ Track 3 (Standard)**| 신규 기능, DB 스키마 변경, 다중 파일 리팩터링 | **정식 2-Phase [Step 0 ➔ Architect ➔ Implement]** | **사전 승인 필수** & `AI Proof` 실측 증거 |
| **💬 Track 4 (General)**| 개념 설명, 일반 지식, 일상 대화, 개발 무관 질문 | 파일 변경 0건, 즉시 대화 응답 | 프로세스 오버헤드 제로 (0건) |

## 🏛️ 2. Track 3 표준 2-Phase 실행 파이프라인 (The High-Assurance Core)

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 🧠 【STEP 0: 세션 부팅 및 헌법 각인 (Constitution Re-Anchoring)】       │
│   • ① 무권대리 금지 ② 사전 승인 필수(Default Deny) ③ AI Proof 실측 의무│
└───────────────────────────────────┬────────────────────────────────────┘
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 1️⃣ 【PHASE 1: 아키텍처 설계 단계 (Architecture Phase)】──→ [/architect]│
│   • views/ 닻 스캔 ➔ 핵심 핀포인트 분석 ➔ views/PLAN 자동 미러링       │
│   • views/IMPLEMENTATION_STATUS.md 대상 모듈 [WIP] 등록                │
└───────────────────────────────────┬────────────────────────────────────┘
                                    ▼
             🛑 【인간 사전 검토 및 승인 게이트 (Human Approval Gate)】
             (인간이 핵심 계획을 검토하고 명시적 사전 승인을 내려야만 착수)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 2️⃣ 【PHASE 2: 구현 및 입증 단계 (Implementation Phase)】──→ [/implement]│
│   • 승인 범위 내 정밀 코딩 ➔ 터미널 실측 테스트 직접 실행 (AI Proof)   │
│   • views/WALKTHROUGH.md 자동 동기화 & 실측 증거 제출                   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    ▼
             👑 【인간 최종 인수 결정 (Human Acceptance Decision)】
             (실측 테스트 원문 로그 확인 ➔ FINAL_ACCEPTED 확정)
```

## ⏸️ 3. 컨텍스트 스위칭 및 끼어들기 프로토콜 (Interrupt & Auto-Catchup)

1. **끼어들기 감지**: 작업 도중 사용자가 Track 1/2/4나 다른 긴급 작업을 지시할 때.
2. **자동 보정**: 진행 중이던 모듈 상태를 `views/IMPLEMENTATION_STATUS.md`에서 `[⏸️ PAUSED]`로 자동 마킹.
3. **복원 안내**: 끼어든 작업 완료 후 원래 진행하던 작업으로의 복귀를 사용자에게 자연스럽게 안내.

---

## 📊 4. 체크리스트 4단 상태 마커 (Status Markers)
- `- [ ]` **`TODO` (미착수)**: 설계 착수 전 또는 구현 대기 상태
- `- [>]` **`WIP` (진행 중)**: 현재 /architect 또는 /implement 작업 중인 상태
- `- [⏸️]` **`PAUSED` (일시 정지)**: 다른 작업 처리로 인해 잠시 중단된 상태
- `- [x]` **`DONE` (완료 및 입증됨)**: 실측 테스트 통과(AI Proof) 및 인간 최종 인수 완료
